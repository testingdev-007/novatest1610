How we'll use GitHub and Copilot today

Everything happens in your browser on GitHub. We read the code, ask Copilot for help, publish the page, look at the result, then make it better. No installs, no extra tools.

The big idea: our improvement loop

We don't try to get it perfect in one go. We repeat a small loop again and again, and every lap makes the page a bit better.

  1. LookOpen the published page and use it like a real user.
  2. ReadFind the file in the Code tab and read the relevant part.
  3. AskUse Copilot to explain, suggest options or help with a change.
  4. ChangeMake one small edit and save (commit) it.
  5. Publish & refreshWait for the page to update, then refresh and check.

Rinse and repeat. Small change, check, small change, check. That's how real teams work too.

Your toolkit

The Code tab

This is home base. Browse the folders, open files and see exactly what the page is made of.

Viewing files

Click a file to read it. You can switch between the code view and editing, and line numbers help you point to exact spots when you ask for help.

Copilot in the repo

Ask Copilot questions about the whole repository straight from the repo page, like "how is this project organised?"

🔍

Copilot in file view

Open a single file and ask Copilot about just that file: what a section does, why something might behave oddly, or how it could be improved.

🌐

The published page

We publish our pages so we can see the real result in a browser tab, exactly as a user would.

💾

Saving changes

Saving a change on GitHub is called a commit. Add a short message saying what you changed and why.

Why no Codespaces?

Codespaces aren't available in our workplace setup, so we're using a browser-only approach instead. It's a great way to work: it's quick to start and you only need GitHub.

Good to know: publishing takes a short moment. If you don't see your change straight away, wait a little and refresh again before assuming something went wrong.

Habits that will save you time

  • One change at a time. It's much easier to see what worked.
  • Always refresh and re-test after publishing.
  • Keep a log of what you noticed, what you asked Copilot and what you changed.
  • Understand before you keep. If you can't explain a change, ask Copilot to explain it.
  • Re-check earlier work. New changes can sometimes affect old ones.
Stuck? Quick checklist
  • Did you save (commit) the change?
  • Did you wait a moment and refresh the published page?
  • Are you looking at the right file and the right page?
  • Can you describe what you expected and what you saw instead?
